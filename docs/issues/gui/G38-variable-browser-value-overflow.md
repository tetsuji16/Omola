# G38: 【不具合】Variable Browser の値が長い指数表記になり、列からはみ出して変数名に重なる

- 難易度: 易 / 依存: なし / 触るファイル: `crates/omola-gui/src/ui/browsers.rs`
- 先に `docs/issues/gui/README.md` を読むこと。

## 不具合の内容(2026-11-09 メンテナ報告)

PID_Controller のシミュレーション後、Variable Browser で

- `4.685711245446625e-6`、`-4.122342692112852e-6`、`4.935971383061921e-11` のような**全桁の指数表記**が出る。
- その文字列が Value 列に収まらず左へはみ出し、**Variable 列の変数名(`w`、`der(phi)` など)に重なって読めない**。

## 原因

`browsers.rs` の `format_value()` は `1e-4 <= |v| < 1e7` 以外で `format!("{v:e}")` を使っており、有効桁を丸めていない。
値は `painter.text(... RIGHT_CENTER ...)` で右寄せに描いているだけで、列の矩形でクリップしていない。

## 実装手順

1. `format_value` を、有効数字 6 桁(`{:.5e}` 相当)で末尾の 0 を落とす形にする。例: `4.685711245446625e-6` → `4.68571e-6`、`1e-6` → `1e-6`、`1.5e7` → `1.5e7`。
2. Value 列・Unit 列・Description 列の文字は、その列の矩形でクリップする(`ui.painter_at(rect)` か `painter.with_clip_rect`)。収まらない場合は末尾を `...` にしてよい。tooltip で全桁(`{v}` = 最短往復表記)を出す。
3. Variable 列の名前も同様に列幅でクリップする(今は列幅を超えると Value 列に入る)。
4. パラメータの入力欄(`J` など)は表示に `format_value` を使っているので、編集開始時に全桁が欲しければ tooltip で十分(入力欄の挙動は変えない)。

## テスト

- `format_value`: `4.685711245446625e-6` → `"4.68571e-6"`、`-4.122342692112852e-6` → `"-4.12234e-6"`、`1e-6` → `"1e-6"`、既存のテスト(`9.8`、`1`、`0.1`、`0`、`-0.25`)が通る。
- 1e-4 と 1e7 の境界前後のテスト。
